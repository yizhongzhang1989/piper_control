# 验证记录（2026-11-26 更新）

本页保留基础 `position_control` 配置、J4 修复及接口验收的历史证据。
后续推荐的 `tcp_tracking` 配置、1.0 m/s 测试和重复定位结果见
[TCP 高速验证](tcp-highspeed-validation.md)；两套参数及各自测试不能混用。

本轮针对用户发现的 J4 静止振荡修正默认参数，并增加原始 CAN 静止验收。
**旧版 17 项软件测试和 10 项真机运动验收没有覆盖这一问题。** 旧真机验收主要
判断运动是否到达终点，随后在保持时仍出现振荡；此前将其描述为最终合格不充分。
以下分开记录当前参数复验与旧记录，不将历史通过结果当作新参数验收。

## J4 修复与当前参数

当前默认 profile 为 `kp=[51,64,60,32,3,3]`、
`kd=[10.375,12.12,6.32,0.53,0.3,0.08]`。本轮只将 J4 基础参数从 `64/2.12`
改为 `32/0.53`；摩擦前馈保持 `0`，重力比例保持 `1`，自适应刚度保持 `2`，
其余关节不变。本次姿态下 J4 实际增益约为 `96/0.918`。参数保存在本仓库的
默认 YAML，启动时加载；覆盖只写运行时设置，原工作空间、臂配置、模型与标定
文件不变。`--control-profile source` 会恢复原增益及原摩擦比例 `0.88`。
完整原因、比较图和实验限制见 [J4 诊断说明](j4-vibration.md)，统计与专项运动
证据见 [本轮诊断数据](j4-vibration-diagnosis.json)。

三次单变量试验先依次降低 J4 阻尼，再降低刚度；改变参数时保持原目标和驱动
运行。以下为各次稳定窗口的原始高速反馈统计：

| 阶段 | J4 基础 kp / kd | 速度 RMS（rad/s） | 电流交流 RMS（A） |
| --- | --- | --- | --- |
| 第一轮原参数基线 | 64 / 2.12 | 0.157497 | 0.148555 |
| 仅 kd 降至 1.0 | 64 / 1.0 | 0.055308 | 0.035228 |
| 仅 kd 再降至 0.53 | 64 / 0.53 | 0.046357 | 0.028226 |
| 仅 kp 降至 32 | 32 / 0.53 | 0.004197 | 0.005255 |

表中候选值来自不同试验窗口，不能理解为每一步速度都严格单调下降；第二轮
自身基线为 `0.045872 rad/s`，仅继续降 kd 并未明显降低速度 RMS，最终降低 kp
才使剩余振荡进一步减小。关节角反馈可能因量化显示完全不变，不能据此判定
电机没有振荡。音频用于辅助比较特定频段，未经声压和时间同步标定。

当前参数下，J4 单独执行 `+0.02 rad` 和返回，各段 `4 s`，均在 `0.01 rad`
终点容差内。运动结束后另取 `4 s` 原始 CAN 保持窗口：

| 项目 | 去程 | 返回 |
| --- | --- | --- |
| 终点误差（rad） | 0.0084808 | 0.0070686 |
| 保持窗口速度 RMS（rad/s） | 0 | 0.0039394 |
| 保持窗口电流交流 RMS（A） | 0.0031078 | 0.0101529 |
| 期望位置在保持窗口内不变 | 是 | 是 |

这里的零表示该采样窗口内反馈量化值为零，不是无限分辨率下的零运动证明。

当前默认参数的 [完整真机验收](hardware-acceptance-j4-fix.json) 于
2026-11-26 10:17 开始，10 项全部通过：movej、外部关节轨迹、movel、movec、
返回运动、关节/TCP/Twist 实时流、流超时保持和 stop 取消。最大终点误差为
`0.00954695 rad`，小于 `0.01 rad`；记录的运动采样速度峰值 `0.113 rad/s`，
仍高于指令速度上限 `0.05 rad/s`，不能把指令上限写成实际速度保证。
完整验收后另外用 `8 s` 返回最初名义目标，终点误差 `0.00998328 rad`，该段记录
速度峰值 `0.111 rad/s`；返回结果保存在上述诊断数据中。

[默认参数重启复验](j4-restart-verification.json) 通过：API 重启前后，六关节目标
完全一致，实测关节位置也一致；J4 基础 `32/0.53` 与摩擦前馈 `0` 自动恢复。
底层驱动 PID 保持 `216086`，原始 CAN 未出现模式或使能帧，采集器发送帧数为零。
该记录验证 API 重启和持久驱动接管，不包含机器人掉电重启。

[15 s 最终静止检查](j4-hold-final.json) 通过：六个关节各收到 `1500` 帧高速反馈
及 `3000` 帧 MIT 命令，采样质量无错误，各路 MIT payload 均只有一种。J4 速度
RMS 为 `0 rad/s`（反馈分辨率内），电流交流 RMS 为 `0.00425135 A`。六关节都
满足本次 `0.01 rad/s` 和 `0.02 A` 门槛；J5 仍有 `0.00530760 rad/s` 速度 RMS，

仍含环境声，不能据此宣称所有声音消失。

新增 `scripts/diagnose_hold.py` 只被动接收 CAN；每关节反馈按实际 `100 Hz`、MIT
按 `200 Hz` 检查采样数、覆盖时间和间隙，再检查速度 RMS 与电流交流 RMS。
本台、本姿态使用 `--max-speed-rms 0.01 --max-current-ac-rms 0.02`，缺数据或
超限均失败。这些阈值是本次实测验收门槛，不是通用安全保证。`--audio` 可选，
输出 80–84 Hz 功率 dBFS，不能解释成 dB SPL。用法见 [真机文档](hardware.md)。

还修复了 API 初始化反馈竞态：等待新鲜、一致的状态和已保持目标后才配置或接管；
持久 MIT 保持的目标未确认时，不回退到实测位置。静态跟踪误差因此不会在重启时
被重新写成目标。仿真未复现固件的高频动态，仿真通过不能作为本问题的稳定性证据。

本轮 Python 回归 **42 项通过**，包括新增的初始化状态到达顺序、过期或缺失目标、

摩擦子步积分回归。软件测试不替代上述真机采样。

同一默认 profile 的 [仿真完整 10 项验收](simulation-acceptance-j4-fix.json) 通过；

## 真机调试发现与修复

设备为 `arm_2 / can1`，采用原重力和摩擦标定。测试只通过通用接口规划小幅运动，
早期指令速度上限设置为 0.08 rad/s。早期运行完成过 movej、关节轨迹、movel、movec、
关节/TCP/Twist 实时流、超时及取消；随后更严格的复验发现终点偏差与退出问题。
当时的完整验收结果保存在 [硬件记录](hardware-acceptance.json)。中间一轮使用 J4
`kp=32, kd=1.5` 的复验在返回运动时出现 0.01033 rad 终点误差，失败记录保留于
[调参前记录](hardware-tuning-before-final.json)；当时提高 J4 增益后重跑全部项目。
后来发现该参数仍有静止振荡，本轮已将其替换为本页开头的 `32/0.53`。

原柔顺增益下 J4 有约 0.025 rad 静态误差。独立位置控制 profile 调整 J1/J4
增益后，曾完整完成一次 0.01 rad 终点容差验收；但实测短时速度高于指令上限，
并在继续复验时观察到异常固件模式与未预期姿态变化。因此这次成功不作为最终
合格依据。指令限速不能保证真实关节速度绝不超过该数值。

最初的 API 退出实现先切固件关节模式再发送当前位置，存在旧目标被采用的风险。
该实现已移除。现在保持 MIT 模式：未修改的驱动由独立 ROS 固定目标进程接管，
带补丁的驱动自行保留超时目标；API 在接管确认前继续发布，不终止底层驱动。
真实的 API→保持进程→API 交回保留了相同目标，前后最大关节变化 0.00063 rad：
[接管记录](hold-handoff-verification.json)。这验证发布接管，不等于固件当前就绪。

## 示教状态原因与恢复进展（2026-11-26）

恢复前，原始 `0x2A1` 状态持续在 `ctrl_mode=2`、`teach_status=1/2` 间切换；总线上没有
观察到开始示教指令。结束示教、Follower 配置及终止执行探测没有恢复稳定控制。
上游 `mit_ready` 可能保留旧值，所以新适配层直接检查原始状态，要求连续 100 ms
确认 CAN/MIT 模式，才置 `command_ready=true`。当时不满足，新运动被拒绝。

用户已确认实体按钮松开、没有卡住。原驱动暂停 0.4 s、以相同六帧 MIT 支撑和
10 Hz 模式请求隔离重试期间，固件仍处于示教状态，且未观察到关节移动。
因此不能把原驱动的结束示教重试循环认定为唯一根因。vendor 已修复独立确认的
旧 `mit_ready` 标志问题，当时原工作空间与运行驱动没有替换；后续有计划启动了
仓库内的修订驱动，原工作空间文件仍保持不变。

随后一次 SDK `reset()` 探测发生了延迟重初始化和实际移动，用户确认当前稳定、
没有碰撞。这次风险判断不充分。进一步查到[厂商明确说明](https://github.com/agilexrobotics/piper_sdk/issues/66#issuecomment-3162642963)
该指令会关闭电机，持续 MIT 支撑不能消除这一行为。不能把复位瞬间的零反馈当成
真实运动量，也不能将短时隔离期间的零运动当作整个复位安全的证据。

之后两轮独立关节使能仍未恢复控制权。[完整摘要](hardware-recovery-2026-11-26.json)
保留前后状态、指令、首个异常与现场确认。当时原驱动继续固定目标输出，不推进
轨迹，并在进一步恢复前请求现场物理支撑。

随后用户确认示教按钮绿灯常亮，短按一次使灯熄灭；再按官方手册先切待机、再切
CAN 控制后，已恢复外部控制。本次持续示教状态的已确认原因是**录制模式未退出**：
按钮虽已松开，录制仍开启，固件因此重复报告 `teach_status=1`。松开瞬时按钮与
关闭录制是两个不同状态，之前仅确认“按钮松开”不足以排除示教录制。

[官方手册 PDF 第 25–26 页](https://cdn.shopify.com/s/files/1/0551/0630/6141/files/PIPER_X_USER_MANUAL.pdf?v=1791861496)
明确规定绿灯常亮为录制、灯灭为结束，短按切换，双击回放；恢复命令控制需先确保
灯灭，再待机，再 CAN。Dashboard 已补充针对录制状态的具体提示，不自动复位。

恢复后曾完成完整 10 项真机运动验收、真机标准 ROS action 与保持/重连接管
验证，结果见本页历史记录；这些记录不覆盖后来发现的 J4 静止振荡。初始姿态保留在
[初始被动 CAN 记录](hardware-initial-passive.json) 的 `positions` 中。
